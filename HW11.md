### **Why Spring Boot? Pros and Cons**

Spring Boot is a framework built on top of the Spring ecosystem. 

It eliminates the need for extensive boilerplate configuration. 

It uses opinionated defaults and auto-configuration so developers can get a production-ready application running with minimal setup. 

**The pros:** 

it reduces configuration overhead, and it has its own embedded server (Tomcat by default) so I don't need to deploy WAR files.

It also has a massive ecosystem of starters for databases, security, messaging, and more, and integrates naturally with Spring's DI (dependency injection) and AOP. 

It also includes Spring Actuator for monitoring out of the box, as well as Promethues and Grafana. 

**The cons:** Sometimes the auto-configuration can make debugging harder when something goes wrong, 

I do not think there are other cons. Spring Boot is a good tool.

### **@Controller vs @RestController**

**@Controller** is the traditional Spring MVC annotation. 

It marks a class as a web controller and works with view resolution. It returns the name of a template (like a Thymeleaf or JSP page) that Spring resolves into an HTML response. 

**@RestController** is a composed annotation that combines @Controller and @ResponseBody. 

Every method in the class automatically serializes its return value directly into the HTTP response body as JSON or XML. It also bypass view resolution entirely. 

Developer usually use @Controller when you are building a server-rendered web application. They use @RestController when you are building a RESTful API that communicates with JSON.

### **@PathVariable vs @RequestParam**

@PathVariable extracts a value embedded directly in the URL path itself, for example in a URL like /users/42, the 42 is part of the path and you bind it with @PathVariable. 

@RequestParam extracts values from the query string appended after a question mark, for example /users?id=42 where id is a query parameter. 

PathVariable is typically used to identify a specific resource, making the URL cleaner and more RESTful.

RequestParam is more suited for optional filters, search terms, pagination, or sorting options where the parameter is auxiliary rather than the identifier of the resource itself.

### **@RequestBody vs @ResponseBody**

**@RequestBody** tells Spring to deserialize the incoming HTTP request body (usually JSON) into a Java object using a message converter like Jackson. 

It is usually on a method parameter when the client is sending data in the body of the request, such as a POST or PUT. 

**@ResponseBody** tells Spring to serialize the return value of a method into the HTTP response body instead of resolving a view. 

When I use @RestController, I get @ResponseBody behavior on every method automatically, so I rarely need to write @ResponseBody explicitly in a REST API context.

### **How to Use GetMapping, PutMapping, PostMapping, DeleteMapping, RequestMapping**

@RequestMapping is the base annotation that can handle any HTTP method and any path. I can specify both the path and the method type on it. 

There are more specific annotations, like: @GetMapping, @PostMapping, @PutMapping, @DeleteMapping. 

They are shortcuts that are equivalent to using @RequestMapping with a specific method type already set. 

@GetMapping is used on methods that retrieve data, 

@PostMapping for creating a resource, 

@PutMapping for fully updating a resource, and 

@DeleteMapping for deleting one. 

In practice I use the specific ones on handler methods for clarity. I can optionally use @RequestMapping at the class level to set a base path that all methods in the controller share.

### **How to Achieve Async in a Spring Boot Application**

I use @Async annotation, as well as @EnableAsync. 

Spring Boot supports asynchronous execution primarily through the @Async annotation combined with enabling async support via @EnableAsync on a configuration class. 

When I annotate a method with @Async, Spring runs it in a separate thread from a configured thread pool rather than blocking the caller's thread. 

The method should return void or a Future or CompletableFuture so the caller can optionally track the result. I can configure the underlying thread pool by defining a TaskExecutor bean to control pool size, queue capacity, and thread naming. 

For reactive, non-blocking async, Spring WebFlux is the alternative approach using Project Reactor with Mono and Flux types, which is suited for high-concurrency scenarios where thread-per-request doesn't scale well.

I can use @RestControllerAdvice and AOP

### **How Does Spring Validate Data**

Spring Validation is used to ensure that incoming data is valid before it reaches the business logic. 

We usually define validation rules in the DTO layer using annotations such as @NotBlank, @Size, @Email, @Min, and @Max. 

Then we add @Valid on the request body parameter in the controller to trigger the validation. 

If the request data violates any validation rule, Spring throws a validation exception and stops the request from continuing. 

We can then use @RestControllerAdvice and @ExceptionHandler to catch the exception and return a customized error response with an appropriate status code and error message.

### **How Does Spring Do Logging**

**Spring uses SLF4J as the logging facade and Logback as the default logging implementation. We can use a Logger or Lombok’s @Slf4j annotation to write logs at different levels such as INFO, DEBUG, WARN, and ERROR.**

In addition, Spring can use AOP to implement centralized logging. Instead of writing log statements in every method, we can define an Aspect and use advices such as @Before, @After, @AfterThrowing, or @Around to intercept method execution automatically. For example, we can log when a method starts, when it finishes, how long it takes to execute, and whether any exception is thrown.

This approach separates logging logic from business logic and avoids duplicated code. It is commonly used for request tracking, exception logging, performance monitoring, and auditing in Spring applications.

### **Cache Hit vs Cache Miss**

A cache hit means the data is already in the cache, so the application can return it immediately without querying the database. A cache miss means the data is not in the cache, so the application must fetch it from the database first and then store it in the cache for future requests. In general, cache hits are fast and reduce database load, while cache misses are slower because they require database access. A good caching strategy aims to increase the cache hit rate and reduce the number of cache misses.

### **Redis: Basic Understanding**

Redis is an in-memory key-value data store that is commonly used as a cache. Unlike traditional databases that store data on disk, Redis stores data in memory, so it can provide very fast read and write performance. In a Spring Boot application, Redis is often used to cache frequently accessed data, such as user information or product information. When the data is found in Redis, the application can return the result directly without querying the database, which reduces database load and improves response time. Redis is also commonly used for session storage, distributed caching, and message communication in distributed systems.

### **@RestControllerAdvice vs @ControllerAdvice**

**@ControllerAdvice is for traditional MVC.**

**@RestControllerAdvice is for REST API and returns JSON responses.**

Both are used for global exception handling in Spring. The main difference is that @ControllerAdvice is usually used in traditional MVC applications that return web pages, while @RestControllerAdvice is used in REST API applications that return JSON responses. In my Spring Boot project, I use @RestControllerAdvice because my controllers are REST APIs and I want to return structured error messages instead of error pages.
