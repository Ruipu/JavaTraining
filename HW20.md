### TDD vs BDD vs DDD

**TDD means Test-Driven Development.** 

In TDD, I write the test before I write the implementation code. The normal process is red, green, and refactor. 

First, I write a test case and let it fail. 

Then I write the minimum code to make the test pass. 

After that, I refactor the code to improve the design. 

TDD helps me make sure the business logic is testable and correct from the beginning.

**BDD means Behavior-Driven Development.** 

BDD focuses more on business behavior and user scenarios. It usually describes the expected behavior **in a “given, when, then” format.** 

For example, given a user has a valid transaction, when the reward API is called, then the system should create reward points for that user. Compared with TDD, BDD is more readable for business people, QA engineers, and developers.

**DDD means Domain-Driven Design.** 

DDD focuses on modeling the business domain correctly. It helps developers **design the system around real business concepts, not just database tables or technical layers.** 

For example, in a reward system, Reward, User, Transaction, and RewardRule can be domain concepts. 

DDD uses ideas like entities, value objects, aggregates, repositories, and domain services. 

**In short, TDD is about writing tests first, BDD is about describing business behavior, and DDD is about designing the application around the business domain.**

### What is JUnit?

JUnit is a testing framework for Java. I use JUnit to write and run automated tests. 

In a Spring Boot project, I usually use JUnit 5. It provides annotations like **`@Test`, `@BeforeEach`, and `@AfterEach`. It also provides assertion methods like `assertEquals`, `assertTrue`, and `assertThrows`.** 

I use JUnit to test service methods, business logic, validation logic, and exception cases.

### What is Mockito?

**Mockito is a mocking framework for Java. I use Mockito to create mock objects for dependencies.** 

For example, when I test the service layer, I do not want to call the real database. So I mock the repository layer and control its return value. 

This helps me isolate the business logic. It also makes the test faster and more stable. Common Mockito annotations are **`@Mock` and `@InjectMocks`.** 

Common methods are **`when(...).thenReturn(...)` and `verify(...)`**. In simple words, JUnit runs the test, and Mockito helps mock the dependencies.

### How do you do the test for your application?

I test my application at different levels. 

First, I write unit tests for the service layer. I use JUnit and Mockito. I mock repositories and external services, then test only the business logic. 

Second, I write controller tests or integration tests. I use Spring Boot Test and MockMvc to test REST APIs. I check the HTTP status code, request body, response body, validation, and exception handling. 

Third, I also use Postman during development to manually test real HTTP requests. 

For database-related integration tests, I can use H2, a test database, or Testcontainers. 

Overall, my testing strategy is unit tests for business logic, integration tests for API flow, and Postman for manual verification.

### Authentication vs Authorization

**Authentication means verifying who the user is.**

**Authorization means verifying what the user can do.** 

For example, when a user logs in with a username and password, that is authentication. After the user logs in, the system checks whether this user can access an admin API. That is authorization. A simple way to say it is: authentication answers “Who are you?” and authorization answers “What are you allowed to access?”

### Encryption vs Hashing vs Encoding

**Encryption is used to protect data confidentiality. It is reversible if we have the correct key.** 

For example, we can encrypt sensitive data before storing it, and decrypt it later with the key. 

**Hashing is one-way. It is not designed to be reversed. It is usually used for passwords.** For example, we do not store the raw password. We store a hashed password with salt. When the user logs in, we hash the input password and compare the result. 

**Encoding is not for security. It is only for data format conversion.** It is reversible and does not need a secret key. For example, Base64 encoding converts binary data into text format. In short, encryption is reversible with a key, hashing is one-way, and encoding is only format conversion.

### How do you secure your application?

I secure my application from different layers. 

First, I use **Spring Security for authentication and authorization.** Users need to log in before accessing protected APIs, and different roles have different permissions. 

Second, I use **JWT or OAuth2 for stateless authentication and authorization.** The client sends the token in the Authorization header, and the backend validates the token before processing the request. 

Third, I **never store raw passwords. I use a strong password hashing algorithm, such as BCrypt.** 

Fourth, I **validate user input to prevent invalid data and common attacks.** For example, I use validation annotations like `@NotNull`, `@NotBlank`, and `@Size`. 

Fifth, **I protect sensitive configuration. I do not hard-code secrets in the source code.** I use environment variables, config files outside Git, or secret management tools. 

Sixth, **I use HTTPS in production**, so data is encrypted during transmission. 

Seventh, I use **proper exception handling and logging. I do not expose internal stack traces or sensitive information to users.** 

**Overall, I secure my application by using authentication, authorization, password hashing, input validation, HTTPS, secure configuration, and proper error handling.**

### What is JWT?

**JWT means JSON Web Token. It is a compact token format used for authentication and authorization.** 

After the user logs in successfully, the server generates a JWT and returns it to the client. The client stores the token and sends it in the Authorization header for later requests.

**A JWT usually has three parts: header, payload, and signature.** 

The header describes the token type and algorithm. 

The payload contains claims, such as user id, username, roles, and expiration time. 

The signature is used to verify that the token has not been changed. JWT is commonly used in stateless authentication. 

The server does not need to store session data for every user. It only needs to verify the token signature and expiration time. One important point is that JWT is signed, but it is not encrypted by default. So we should not put sensitive information like passwords inside the JWT payload.

### What is OAuth2?

**OAuth2 is an authorization framework. It allows one application to access resources on behalf of a user without directly sharing the user’s password.** 

For example, when a user logs into an application with Google, the application does not get the user’s Google password. 

Instead, Google issues an access token. Then the application can use that token to access allowed user information, such as basic profile or email, depending on the scope. 

OAuth2 has several important roles. 

The resource owner is the user. 

The client is the application that wants access. 

The authorization server issues tokens. 

The resource server stores the protected resources. 

**In Spring Boot, OAuth2 is often used with Spring Security.** 

We can use it for social login, single sign-on, and secure API access. In short, OAuth2 is mainly about delegated authorization. It lets one application access protected resources on behalf of a user by using tokens instead of passwords.
