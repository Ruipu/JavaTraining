### **What is Angular, and why is it considered a framework rather than just a library?**

**Angular is a front-end framework developed by Google for building modern web applications.** 

It provides a complete set of tools for application development, including components, routing, forms, dependency injection, HTTP communication, and testing. 

**Unlike a library that focuses on one specific feature, Angular provides a complete structure and development pattern.** 

**Developers follow Angular’s architecture instead of building everything from scratch, which makes it a framework rather than just a library.**

### **What is a Single Page Application (SPA), and why is Angular commonly used to build SPAs?**

**A Single Page Application, or SPA, loads a single HTML page when the application starts.** 

After that, only the necessary data and page content are updated without refreshing the entire browser page. This creates a faster and smoother user experience. 

Angular is commonly used for SPAs because it includes built-in routing, data binding, state management, and component-based architecture, making it easy to build large interactive applications.

### **Why does Angular use TypeScript by default, and what benefits does TypeScript provide in large projects?**

Angular uses TypeScript because **it adds static typing, object-oriented programming features, and better tooling on top of JavaScript.** 

TypeScript helps developers detect errors during compilation instead of waiting until runtime. 

In large projects, it improves code readability, maintainability, and collaboration because variable types, interfaces, and class structures are clearly defined. 

Modern IDEs also provide better code completion and navigation when using TypeScript.

### **What does “component-based architecture” mean in Angular? Give an example of what a component contains.**

**Component-based architecture means an application is divided into many small, independent, and reusable components.** 

Each component is responsible for a specific part of the user interface and its related logic.

 **A typical Angular component contains a TypeScript class for business logic, an HTML template for the user interface, a CSS or SCSS file for styling, and metadata defined by the `@Component` decorator.** 

For example, an employee list, navigation bar, or login form can each be implemented as separate components.

### **Angular is sometimes described as following MVC ideas. In your own words, what does “separation of concerns” mean?**

**Separation of concerns means different parts of the application have different responsibilities.** 

The user interface is responsible for displaying information, business logic handles application behavior, and data management is responsible for storing and retrieving data. 

By separating these responsibilities, the code becomes easier to understand, maintain, test, and extend. A change in one part of the application is less likely to affect the others.

### **What is two-way data binding, and how does it reduce manual DOM manipulation?**

Two-way data binding automatically keeps the user interface and the application data synchronized. 

**When the data changes, the page updates automatically. When the user modifies an input field, the corresponding data model is also updated automatically.** 

This removes the need to manually find HTML elements and update the DOM using JavaScript, which reduces repetitive code and makes development more efficient.

### **What is Dependency Injection (DI), and why does it improve testability and loose coupling?**

**Dependency Injection is a design pattern where Angular creates and provides the required objects instead of letting a class create them directly.** 

A component simply requests the services it needs, and Angular injects those dependencies automatically. 

This reduces coupling between classes because each class depends on interfaces or services instead of creating concrete objects. 

It also improves testability because mock services can easily replace real services during unit testing.

### **What is routing in Angular, and what problem does it solve in a front-end application?**

**Routing allows users to navigate between different views without reloading the entire page.** 

Each URL is mapped to a specific component, so Angular displays the correct content based on the current route. 

Routing makes a Single Page Application behave like a traditional multi-page website while keeping the application fast. 

It also supports features such as navigation, parameter passing, route protection, and lazy loading.

### **What is Node.js, and why do we need it for Angular development?**

**Node.js is a JavaScript runtime that allows JavaScript to run outside the browser.** 

Angular development relies on Node.js because the Angular CLI, npm, build tools, and development server all run on Node.js. 

Although the Angular application eventually runs in the browser, Node.js provides the environment needed to install packages, compile TypeScript, build the project, and start the local development server.

### **What is npm, and how is it similar to Maven/Gradle in the Java ecosystem?**

**npm is the Node Package Manager used to install and manage JavaScript libraries and project dependencies.** 

It downloads packages from the npm registry and records them in the project configuration. 

It is similar to Maven or Gradle in Java because all three tools manage dependencies, download required libraries automatically, and help build projects. 

This allows developers to use external packages without manually copying files into the project.

### **What is Angular CLI, and name at least 3 things it helps you do?**

**Angular CLI is the official command-line tool for Angular development.** 

It automates many common development tasks and improves developer productivity. 

It can generate components, services, modules, and other project files automatically. 

It can also build the application for production, start a local development server, run unit tests, execute end-to-end tests, and create a new Angular project with the recommended project structure.

### **What command do you use to check your installed Node and npm versions?**

The installed Node.js version can be checked by running `node -v`, and the npm version can be checked by running `npm -v`. These commands help verify that the correct development environment is installed before creating or running an Angular project.

### **What does ng new do, and why should you run it in the correct workspace/folder?**

**The `ng new` command creates a brand new Angular project with the standard project structure, configuration files, dependencies, and build settings.** 

It also installs the required npm packages automatically. It should be run in the correct workspace or parent folder because Angular creates a new project directory at the current location. Choosing the correct folder helps keep projects organized and avoids creating projects inside the wrong directory.

### **What is the purpose of package.json and package-lock.json? Why is package-lock.json important in team projects?**

**The `package.json` file describes the project and lists its dependencies, scripts, metadata, and version requirements.** 

It tells npm which packages the project needs but usually specifies version ranges instead of exact versions.

**The `package-lock.json` file records the exact versions of every installed dependency, including indirect dependencies.** 

This ensures every developer installs the same package versions, making builds more consistent across different environments. 

In team projects, it helps prevent unexpected behavior caused by different dependency versions and improves reproducibility during development, testing, and deployment.
