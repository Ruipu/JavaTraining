### **What are the four stages of an Angular project lifecycle?**

**An Angular project typically goes through four stages: project creation, development, build, and deployment.** 

The project is first created using Angular CLI, which generates the project structure and installs dependencies. 

During development, developers write code and test the application locally. 

The build stage compiles and optimizes the application for production. 

Finally, the generated files are deployed to a web server so users can access the application through a browser.

### **What does ng serve do during the development phase?**

**The `ng serve` command starts a local development server and launches the Angular application for development.** 

It compiles the project, serves it through a local web server, and allows developers to view the application in a browser. 

It also watches the project files and automatically reloads the application whenever code changes are saved.

### **What happens “behind the scenes” when you run ng serve?**

When `ng serve` is executed, Angular compiles TypeScript into JavaScript, processes HTML templates and CSS files, bundles the application, starts a local development server, and continuously watches the project for file changes. 

Whenever a source file is modified, Angular recompiles only the affected parts and refreshes the browser automatically, allowing developers to see updates immediately.

### **Why is the development environment not designed for production usage?**

**The development environment is optimized for fast coding and debugging rather than performance.** 

It includes debugging information, source maps, detailed error messages, and automatic file watching. 

These features increase application size and reduce performance. 

In production, users only need the optimized application, so the development environment is not suitable for deployment.

### **What does ng build do, and why is it important to understand that Angular does not run in production?**

**The `ng build` command compiles the Angular application into static files that can be deployed to a web server.** 

Angular itself does not run on the production server. 

Instead, the server simply delivers the generated HTML, JavaScript, CSS, and other static resources to users’ browsers. 

The browser executes the application, making Angular a client-side framework rather than a server-side runtime.

### **During the build process, what optimizations happen to the code?**

During the build process, Angular performs several optimizations to improve performance. 

TypeScript is compiled into JavaScript, 

unused code is removed through tree shaking, 

multiple files are bundled together, JavaScript and CSS are minified to reduce file size, 

and static assets are optimized. 

**These steps make the application load faster and reduce network traffic.**

### **What is the dist folder, and what kind of files get deployed from it?**

**The `dist` folder contains the final production-ready version of the Angular application after the build process completes.** 

It usually includes optimized HTML, JavaScript, CSS, image files, fonts, and other static resources. 

These files are the ones deployed to a web server such as Nginx, Apache, or cloud hosting services.

### **Why does Angular provide built-in testing support, and why does that matter in enterprise environments?**

**Angular includes built-in support for unit testing and integration testing because testing is an essential part of enterprise software development.** 

Automated tests help verify that new changes do not break existing functionality. 

They improve software quality, reduce production defects, and make refactoring safer. 

In large projects with many developers, testing also increases confidence when releasing new features.

### **What is TypeScript, and what does it add on top of JavaScript?**

**TypeScript is a programming language developed by Microsoft that extends JavaScript.** 

It adds features such as static typing, interfaces, classes, generics, access modifiers, and decorators. 

TypeScript code is compiled into standard JavaScript before it runs in the browser. These additional features help developers write more organized and reliable code.

### **Why does TypeScript help in large applications (runtime vs compile time errors, refactoring, maintainability)?**

TypeScript detects many programming errors during compilation instead of waiting until the application runs. 

This allows developers to fix problems earlier in the development process. Strong typing also makes refactoring safer because IDEs can identify incorrect changes automatically. 

In large applications, TypeScript improves code readability, consistency, and long-term maintainability, making collaboration easier for development teams.

### **What is npm, and how is package.json similar to pom.xml or build.gradle?**

**npm is the default package manager for Node.js and is responsible for installing and managing project dependencies.** 

The `package.json` file stores information about the project, including dependency definitions, scripts, project metadata, and version requirements. 

It serves a similar purpose to `pom.xml` in Maven or `build.gradle` in Gradle because all of them define project dependencies and build-related configuration.

### **What is a Single Page Application (SPA), and how is it different from a traditional multi-page web application?**

**A Single Page Application loads a single HTML page when the application starts and updates only the necessary content as users navigate between different views.** 

**The browser does not reload the entire page for every action. In contrast, a traditional multi-page application requests a completely new HTML page from the server whenever the user moves to another page.** 

SPAs usually provide a smoother and faster user experience because much of the application logic runs in the browser.

### **What are the three main parts of an Angular component, and what does each part do?**

**An Angular component mainly consists of a TypeScript file, an HTML template, and a CSS or SCSS stylesheet.** 

The TypeScript file contains the component’s business logic and data. 

The HTML template defines the user interface and displays the data. 

The stylesheet controls the appearance and layout of the component. 

Together, these parts make each component independent, reusable, and easy to maintain.

### **When you run ng generate component my-first-component, what files are created and what change happens in app.module.ts?**

**When the `ng generate component my-first-component` command is executed, Angular automatically creates a new folder containing several files.** 

These typically include a TypeScript component file, an HTML template file, a CSS or SCSS stylesheet, a unit test file, and the component metadata. 

Angular also updates `app.module.ts` automatically by importing the new component and adding it to the module’s declarations list, making the component available for use within the application.
