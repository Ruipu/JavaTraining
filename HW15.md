### **JDBC vs Hibernate**

**JDBC is a low-level API that allows Java applications to communicate directly with a database.** 

**Developers must write SQL statements manually, execute queries, handle connections, process result sets, and map database records to Java objects themselves.** 

Hibernate is an ORM framework built on top of JDBC. 

Instead of working directly with SQL and database tables, **developers work with Java objects, and Hibernate automatically generates and executes the necessary SQL statements.** 

JDBC provides more control and can be more lightweight, **while Hibernate improves productivity, reduces boilerplate code, and offers advanced features such as caching, lazy loading, and entity lifecycle management.**

### **Statement vs PreparedStatement vs CallableStatement**

Statement is used to **execute static SQL queries and requires the database to compile the SQL every time it is executed.** 

PreparedStatement is used for parameterized queries and precompiles the SQL statement, which improves performance and security (avoid picking up all the columns and raws from tabulate.). 

It is the most commonly used option in enterprise applications because **it helps prevent SQL injection.** 

CallableStatement is used to execute stored procedures defined inside the database and supports input and output parameters, making it useful when business logic is implemented at the database level.

### **How to Prevent SQL Injection?**

**Use PreparedStatement!!!!!!**

The most effective way to prevent SQL injection is to use PreparedStatement instead of dynamically concatenating user input into SQL strings, or using `statement`. 

PreparedStatement separates user input from SQL logic, ensuring that user-supplied values are treated as data rather than executable SQL code. 

Additional protection includes input validation, least-privilege database accounts, and the use of ORM frameworks such as Hibernate, which automatically generate parameterized queries.

### **What is ORM**

ORM stands for Object Relational Mapping. 

It is a technique that maps **Java objects to relational database tables** and **database records back to Java objects.** 

ORM allows developers to work with objects **rather than writing SQL for every database operation.** 

This improves code readability, maintainability, and productivity by bridging the gap between object-oriented programming and relational databases.

### **JPA vs Hibernate**

JPA is a specification that **defines a standard API for object-relational mapping in Java.**

Hibernate is one of the most popular implementations of that specification. 

JPA defines what persistence operations should look like, **but it does not provide the actual implementation.** 

**Hibernate provides the underlying implementation** that performs the persistence work. In most Spring Boot applications, developers program against JPA interfaces while Hibernate executes the actual database operations behind the scenes.

### **What are the Persistent States in Entity Lifecycle**

An entity typically goes through **four lifecycle states.** 

1. **The transient state refers to a newly created object that is not associated with any persistence context and does not exist in the database.** 
2. **The persistent state** refers to **an entity that is managed by Hibernate**, meaning any changes made to the object are automatically synchronized with the database. 
3. **The detached state** occurs when an entity was previously managed but is **no longer associated with an active session, so changes are not automatically tracked.** 
4. The removed state represents **an entity that has been marked for deletion** and will be **removed** from the database when the transaction is committed.

### **Mapping Relationship**

Entity (Mapping) relationships describe **how tables are connected in a relational database.** 

A one-to-one relationship means one record is associated with exactly one record in another table, such as an employee and a parking space. 

A one-to-many relationship means one parent record can have multiple child records, such as a department containing many employees. 

A many-to-one relationship is the reverse, where many employees belong to a single department. 

A many-to-many relationship allows records from both tables to be associated with multiple records in the other table, such as students enrolling in multiple courses and courses having multiple students.

### **What is the Cascade Type**

Cascade type determines whether operations performed on a parent entity should automatically propagate to related child entities. For example, if cascade persist is configured, saving the parent entity will automatically save the child entities as well. Similarly, cascade remove will automatically delete child entities when the parent is deleted. Cascade functionality simplifies entity management by ensuring related objects remain consistent without requiring explicit operations on every entity.

### **What is the Fetch Type**

Fetch type determines when associated entities are loaded from the database. Eager fetching loads related entities immediately whenever the parent entity is retrieved. Lazy fetching delays loading until the related data is actually accessed. Eager fetching can simplify access to related data but may negatively impact performance by loading unnecessary information. Lazy fetching is generally preferred in enterprise applications because it reduces unnecessary database queries and memory usage.

### **What is the First-Level Cache and Second-Level Cache**

The first-level cache **is built into Hibernate and exists at the session level.** 

**Every session maintains its own cache**, so if the same entity is requested multiple times within the same session, Hibernate retrieves it from memory rather than executing additional database queries. 

The second-level cache is **shared across multiple sessions and must be explicitly configured**. 

It stores frequently accessed data at the application level, reducing database traffic and improving performance for read-heavy systems.

### **Left Join vs Right Join vs Inner Join vs Outer Join vs Cross Join**

An inner join returns only records that have matching values in both tables. 

**A left join** returns all records from the left table and matching records from the right table, with null values returned when no match exists. 

**A right join** works the same way but prioritizes the right table instead (reverse the last one).

**An outer join returns all matching and non-matching records** from both tables, preserving data from both sides regardless of whether a match exists. 

**A cross join** produces the Cartesian product of two tables, **meaning every row from the first table is combined with every row from the second table.** Because of the potentially huge result set, cross joins are used much less frequently than other join types.

### **Union vs Union All**

Both UNION and UNION ALL are used to combine the results of multiple queries into a single result set. The difference is that 

- **UNION automatically removes duplicate rows, while UNION ALL keeps all rows,** including duplicates. Because UNION performs additional duplicate-checking operations, it is generally slower than UNION ALL. If duplicate records are acceptable or expected, UNION ALL is usually preferred for better performance.
