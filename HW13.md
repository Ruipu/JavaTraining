### **SQL vs NoSQL Database**

SQL and NoSQL are two major categories of databases. 

**SQL databases,** also known as relational databases, store data in tables with rows and columns. They use Structured Query Language (SQL) to query and manage data. 

SQL databases usually provide strong consistency, support transactions, and work well for structured data with clear relationships. Common examples include MySQL, PostgreSQL, and Oracle Database.

**NoSQL databases** were introduced to handle large-scale distributed systems and flexible data structures. 

They do not require a fixed schema and can store documents, key-value pairs, graphs, or column-oriented data. 

They are generally easier to scale horizontally and are often used in high-traffic applications. Common examples include MongoDB, Redis, and Amazon DynamoDB. 

In general, SQL databases are preferred when data consistency and transactions are critical, while NoSQL databases are often chosen for scalability and flexibility.

### **What is Database Normalization?**

Database normalization is the process of organizing data to reduce redundancy and improve consistency. The goal is to make sure that each piece of information is stored in only one place, which reduces data duplication and makes maintenance easier. 

**The most common normalization levels are the First Normal Form (1NF), Second Normal Form (2NF), and Third Normal Form (3NF).**

1NF requires every column to contain only a single value. 

2NF eliminates partial dependencies by ensuring that non-key columns fully depend on the primary key. 

3NF removes transitive dependencies, meaning one non-key column should not depend on another non-key column. For example, if age can be calculated from birth year, storing both values may violate Third Normal Form.

Although normalization improves data consistency, it can also introduce more tables and more join operations. In real-world systems, especially high-traffic applications, **developers sometimes intentionally use denormalization by storing redundant data to improve query performance.** Therefore, normalization is a best practice, but it is always a trade-off between consistency and performance.

### **Vertical Scaling vs Horizontal Scaling**

Scaling refers to increasing the capacity of a system to handle more traffic and workload. 

**Vertical scaling** means upgrading a single server **by adding more CPU, memory, or storage.** 

It is relatively simple because the application architecture usually does not need to change. However, vertical scaling has physical hardware limits and can become very expensive. It also creates a single point of failure because everything still depends on one machine.

**Horizontal scaling** means adding more servers and distributing the workload among them. This approach is commonly used in modern cloud-based applications. A load balancer can distribute requests across multiple backend servers, allowing the system to handle much larger traffic volumes. 

Horizontal scaling provides better fault tolerance and scalability, but it introduces additional complexity, such as data synchronization and distributed system management. 

In modern microservice architectures, horizontal scaling is generally preferred because it supports continuous growth and high availability.

### **What is ACID?**

ACID is a set of properties that guarantee reliable database transactions. ACID stands for Atomicity, Consistency, Isolation, and Durability.

**Atomicity** means that a transaction is treated as a single unit of work. Either all operations succeed or all operations fail. 

**Consistency** means that the database remains in a valid state before and after the transaction. 

**Isolation** ensures that multiple concurrent transactions do not interfere with each other. 

**Durability** guarantees that once a transaction is committed, the data will remain permanently stored even if the system crashes afterward.

ACID is especially important in systems where data accuracy is critical, such as banking, payment processing, and financial applications. 

These guarantees help ensure that transactions remain correct and reliable under concurrent access and unexpected failures.

### **What is CAP Theorem?**

CAP Theorem is one of the most important concepts in distributed systems. It states that a distributed system can only fully guarantee two out of three properties: **Consistency, Availability, and Partition Tolerance.**

**Consistency** means that all nodes see the same data at the same time. 

**Availability** means that every request receives a response, even if some nodes fail. 

**Partition Tolerance** means that the system can continue operating even when network failures occur between different nodes.

According to the CAP theorem, when a network partition happens, a system must choose between consistency and availability. Some systems prioritize consistency and partition tolerance, while others prioritize availability and partition tolerance. Traditional relational databases are often considered closer to the Consistency and Availability side because they typically run as a single centralized system. Distributed NoSQL databases usually choose either CP or AP depending on their design goals. Understanding CAP helps engineers make architectural decisions based on business requirements, performance expectations, and reliability needs.

                          salary  NUMERIC(10,2)
